## 1. วัตถุประสงค์การทดลอง
1. สามารถใช้เครื่องมือวิเคราะห์ข้อผิดพลาด (Serial Logs, Logic Probe, Memory Dump) ในการสืบหาสาเหตุของปัญหาในระบบสมองกลฝังตัวได้
2. เข้าใจอาการและวิธีแก้ไขปัญหา **จอมืดสนิท (Black Screen)** จากคำสั่ง Charge Pump และขา Hardware Reset
3. เข้าใจอาการและวิธีแก้ไขปัญหา **ภาพพิกเซลเพี้ยน (Garbled Display)** จากสูตรคณิตศาสตร์ระดับบิตใน Framebuffer
4. เข้าใจอาการและวิธีแก้ไขปัญหา **ภาพกลับหัว 180 องศา (Upside-down Display)** จากการตั้งค่า Segment Re-map และ COM Direction
5. สามารถจัดทำแบบฟอร์มรายงานการตรวจพิสูจน์หลักฐานความผิดพร่องทางวิศวกรรม (**Engineering Forensic Incident Report**) ได้อย่างถูกต้องตามมาตรฐาน

## 2. การวิเคราะห์กรณีศึกษาข้อผิดพลาด 4 รูปแบบ (The 4 Fault Cases)

| กรณีศึกษา | อาการทางกายภาพ | สาเหตุต้นตอ (Root Cause) | แนวทางแก้ไขทางวิศวกรรม |
| :--- | :--- | :--- | :--- |
| **Case 1: The Black Screen Mystery** | หน้าจอดับสนิท ไม่มีแสง | ขา RES ค้างที่สถานะ LOW หรือคำสั่งเปิด Charge Pump ส่งค่าผิดพลาดเป็น `0x10` (Disable) | ดึงขา RES เป็น HIGH หลังหน่วงเวลา และแก้ไขคำสั่งเป็น `oled_send_cmd(0x8D); oled_send_cmd(0x14);` พร้อม `0xAF` |
| **Case 2: Garbled Screen Forensics** | หน้าจอติดแต่ภาพแตกเละ อ่านไม่ออก | สูตรบิตแมปลืมหาร 8 `x + y * 128` ทำให้ Index ล้น หรือใช้ `y / 8` แทนโมดูลัส `y % 8` | แก้ไขสูตร: `index = x + (y / 8) * 128;` และ `bit_offset = y % 8;` |
| **Case 3: Upside-down Display** | ภาพและข้อความกลับหัว 180° แถบสีเหลืองไปอยู่ล่าง | ค่า Default Reset ของชิป SSD1306 เริ่มต้นที่ `0xA0` (SEG0) และ `0xC0` (COM0) | เพิ่มคำสั่ง `0xA1` (Segment Remap กลับซ้ายขวา) และ `0xC8` (COM Scan กลับบนล่าง) |
| **Case 4: Telemetry Mismatch** | ตัวเลขบนเว็บค้าง ข้อมูลขาดช่วง | ลืมพิมพ์ `\n` ท้ายแพ็กเก็ต Serial หรือ Baudrate ไม่ตรงกัน | เติม `\n` ให้กับคำสั่ง `printf("ADC:%d\n", ...)` และตั้ง Baudrate `115200` ให้ตรงกัน |

## 4. คำถามท้ายการทดลอง Lab 9.4

### ข้อ 1: หากสายสัญญาณ SCK (GPIO 18) หลุดออกจาก Breadboard ผลการทำงานของหน้าจอ OLED จะแสดงอาการอย่างไร และเพราะเหตุใด?
- **ตอบ:** **หน้าจอ OLED จะค้างที่ภาพเดิมก่อนสายจะหลุด หรือจอมืดสนิทหากสายหลุดตั้งแต่ตอนเปิดเครื่อง** เพราะสัญญาณ SCK (Serial Clock) คือจังหวะสัญญาณนาฬิกาหลักที่ตัวรับ (SSD1306) ใช้ในการอ่านระดับแรงดันที่ขา MOSI (Data Latch) เมื่อไม่มีสัญญาณ Clock ชิป SSD1306 จะไม่รับรู้คำสั่งหรือข้อมูลพิกเซลใหม่ที่ส่งเข้ามาเลย ทำให้ไม่สามารถเริ่มกระบวนการตั้งค่าเรจิสเตอร์หรือเปลี่ยนข้อมูลในแรมภาพได้

### ข้อ 2: ในการวิเคราะห์บั๊กเชิงนิติวิทยาศาสตร์ เหตุใดการทำ Hex Dump หน่วยความจำ Framebuffer จึงเป็นหลักฐานที่น่าเชื่อถือกว่าการมองด้วยสายตาเปล่าบนหน้าจอ?
- **ตอบ:** เพราะการมองด้วยสายตาเปล่าบนหน้าจอเป็นเพียง **การสังเกตผลลัพธ์ปลายทาง (Symptom)** ซึ่งอาจเกิดความผิดพลาดได้จากหลายปัจจัย เช่น การต่อสายสัญญาณหลุดหลวม, วงจรทวีแรงดันไฟล้มเหลว, หรือคำสั่งกำหนดทิศทางการสแกนผิดพลาด แต่การทำ **Hex Dump หน่วยความจำ Framebuffer บน SRAM ของ ESP32** เป็นการพิสูจน์ **ความถูกต้องของตรรกะและอัลกอริทึมต้นทาง (Root Logic & Mathematical Correctness)** ว่าสูตรบิตแมปและตารางฟอนต์ทำงานคำนวณตำแหน่งพิกเซลถูกต้องตามความเป็นจริงหรือไม่ ทำให้สามารถแยกแยะได้ชัดเจนว่าปัญหาเกิดจากโค้ดฝั่งซอฟต์แวร์หรือเกิดจากระบบฮาร์ดแวร์ภายนอก
