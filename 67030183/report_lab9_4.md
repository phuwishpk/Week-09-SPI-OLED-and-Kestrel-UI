## 1. วัตถุประสงค์
1. สามารถใช้เครื่องมือวิเคราะห์ข้อผิดพลาด (Serial Log และ Memory Dump) ในการหาสาเหตุของปัญหาในระบบสมองกลฝังตัว
2. เข้าใจและแก้ไขปัญหาจอมืด (Black Screen) จากคำสั่ง Charge Pump และขา Hardware Reset

5. สามารถบันทึกรายงานการตรวจสอบข้อผิดพลาดทางวิศวกรรม (Engineering Forensic Incident Report) ตามแบบฟอร์ม

## 2. กรณีศึกษาข้อผิดพลาด 4 รูปแบบ (Fault Cases)

| กรณีศึกษา | อาการที่พบ | สาเหตุ | การแก้ไข |
| :--- | :--- | :--- | :--- |
| **Case 1: Black Screen** | หน้าจอดับสนิท ไม่มีแสง | ขา RES ค้างที่สถานะ LOW หรือส่งคำสั่ง Charge Pump เป็น `0x10` (Disable) | ดึงขา RES เป็น HIGH และแก้ไขคำสั่งเป็น `0x8D, 0x14` พร้อมส่ง `0xAF` |
| **Case 2: Garbled Screen** | จอติดแต่ภาพลายเส้นแตก อ่านไม่ออก | สูตรบิตแมปลืมหาร 8 `x + y * 128` ทำให้ Index ล้น หรือใช้ `y / 8` แทนโมดูลัส `y % 8` | ใช้สูตร `index = x + (y / 8) * 128;` และ `bit_offset = y % 8;` |
| **Case 3: Upside-down Display** | ภาพและข้อความกลับหัว แถบสีเหลืองอยู่ล่าง | SSD1306 เริ่มต้นด้วยค่า Default Reset `0xA0` (SEG0) และ `0xC0` (COM0) | เพิ่มคำสั่ง `0xA1` (Segment Remap) และ `0xC8` (COM Scan Direction) |
| **Case 4: Telemetry Mismatch** | ตัวเลขบนเว็บค้าง ข้อมูลขาดช่วง | ลืมส่ง `\n` ท้ายแพ็กเก็ต Serial หรือตั้งค่า Baudrate ไม่ตรงกัน | ใส่ `\n` ท้ายคำสั่ง `printf("ADC:%d\n", ...)` และใช้ Baudrate 115200 |

```text
                    ENGINEERING FORENSIC INCIDENT REPORT

1. รหัสนักศึกษา / ผู้รายงาน: 67030183
2. กรณีศึกษาข้อผิดพลาด (Fault Case No.): [  ] Case 1   [  ] Case 2   [x] Case 3   [  ] Case 4
3. อาการที่ตรวจพบทางกายภาพ (Observed Physical Symptoms):
   - หน้าจอ OLED ติดสว่างและข้อความคมชัดปกติ ไม่มี Dead Pixel
   - ข้อความ "HELLO WORLD" และ "ID: 67030183" แสดงผลกลับหัว 180 องศา
   - แถบสีเหลือง (16 แถวบน) ของจอ Dual-Color สลับไปอยู่ขอบล่างแทนขอบบน
4. สมมติฐาน (Hypothesis):
   - ชิป SSD1306 เริ่มต้นด้วยค่าเริ่มต้นของ Segment Address และทิศทางการสแกนของ COM Output
     โดยยังไม่ได้ตั้งค่า Re-map ให้สอดคล้องกับทิศทางการติดตั้งของโมดูล
5. หลักฐานที่ตรวจพบ (Discovered Forensic Evidence):
   - ในฟังก์ชัน oled_init_display() เริ่มต้นส่งเพียงคำสั่งเปิดจอ แต่ยังขาดคำสั่งกำหนดทิศทางการสแกน:
     Segment Re-map อยู่ที่ 0xA0 (Column 0 maps to SEG0)
     COM Output Scan อยู่ที่ 0xC0 (Scan from COM0 to COM[N-1])
6. การแก้ไขและผลการยืนยัน (Corrective Action & Verification):
   - เพิ่มคำสั่งกำหนดทิศทางสแกนในฟังก์ชัน oled_init_display():
     oled_send_cmd(0xA1); // สลับทิศทางแนวนอน (Column 127 maps to SEG0)
     oled_send_cmd(0xC8); // สลับทิศทางแนวตั้ง (Scan from COM[N-1] to COM0)
   - ผลการทดสอบ: แถบสีเหลืองกลับขึ้นมาอยู่ด้านบน และข้อความแสดงผลในทิศทางปกติ
================================================================================
```

## 4. สรุปคำถามท้ายการทดลอง

### ข้อ 1: หากสายสัญญาณ SCK (GPIO 18) หลุดออกจาก Breadboard ผลการทำงานของจอ OLED จะเป็นอย่างไร?
- **ตอบ:** **หน้าจอจะค้างที่ภาพเดิมก่อนสายหลุด หรือจอดับสนิทหากสายหลุดตั้งแต่ตอนเปิดเครื่อง** เนื่องจากสัญญาณ SCK (Serial Clock) เป็นสัญญาณนาฬิกาที่ตัวรับใช้สลักข้อมูล (Latch data) เมื่อไม่มีสัญญาณ Clock ชิป SSD1306 จะไม่สามารถรับรู้คำสั่งหรือข้อมูลพิกเซลใหม่ได้

### ข้อ 2: ทำไมการทำ Hex Dump Framebuffer จึงเป็นหลักฐานที่น่าเชื่อถือกว่าการดูด้วยตาเปล่าบนหน้าจอ?
- **ตอบ:** เพราะการดูด้วยตาเปล่าเป็นการดู **ผลลัพธ์ปลายทาง (Symptom)** ซึ่งอาจคลาดเคลื่อนได้จากหลายปัจจัย เช่น สายสัญญาณหลุดหลวม หรือคำสั่งทิศทางสแกนผิดพลาด แต่การทำ **Hex Dump บน SRAM ของ ESP32** เป็นการยืนยัน **ความถูกต้องของตรรกะในหน่วยความจำ (Root Logic)** ว่าสูตรบิตแมปและฟอนต์คำนวณตำแหน่งพิกเซลถูกต้องหรือไม่ ทำให้สามารถแยกแยะได้ว่าปัญหาเกิดจากโค้ดซอฟต์แวร์หรือเกิดจากการเชื่อมต่อทางฮาร์ดแวร์
